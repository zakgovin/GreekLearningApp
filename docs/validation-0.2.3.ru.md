# Проверка версии 0.2.3

Причина +1 после ошибки: старая формула немедленно обрезала штраф на нуле, поэтому следующий правильный ответ давал чистый +1. Теперь транзакционная таблица session_balances хранит расчёт в рамках текущей тренировки, а progress всегда остаётся 0–25. После ошибки на нуле исправление компенсирует ошибку и оставляет 0. Верхний предел не накапливает скрытого положительного запаса. Новая тренировка начинает расчёт от текущего видимого прогресса.

assembleDebug, все 45 Android/JVM-тестов и lintDebug завершились успешно. Новые проверки: ошибка на нуле → перезапуск → правильный ответ → 0; повторная доставка ошибки не дублирует штраф; новая тренировка не наследует отрицательный остаток; правильный на 25 → ошибка → 24; миграция базы версии 2 до 3 сохраняет прогресс; полный сценарий «Выбрать слово» с ошибкой, выходом/продолжением, правильным выбором, завершением аудио и итоговым изменением 0%. Ранее существующая миграция версии 1 также проверена до схемы 3. Android-сценарии выполнялись в Robolectric API 28.
