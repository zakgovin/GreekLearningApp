# Проверка версии 0.5.2

ТО_RU/TO_EL: итог вопроса +1% при 0 ошибках, +0,5% при одной, −1% при двух и более. Первая ошибка меняет только состояние вопроса/очередь закрепления, вторая начисляет −1; последующие ошибочные нажатия и окончательный верный ответ сохраняют отрицательный итог. LISTEN_EASY, MATCH и остальные режимы сохраняют прежние правила. Пояснения двух режимов обновлены, ложная подпись «−1%» после первой ошибки заменена нейтральной.

База 6→7 добавляет choice_scores с числом ошибок и суммарным начислением по practiceKey. В Store применяется разница между новым и прежним суммарным итогом, в одной транзакции с попыткой, сессионным балансом и дневным завершением. choiceErrors/choiceTarget сохраняются в журнале; восстановление из JSON реконструирует состояние. Для незавершённых старых вопросов прежние штрафы учитываются при следующем ответе и корректируются до нового итога. Завершённые исторические вопросы сохраняют начисления своей версии; миграция не переписывает уже сохранённые проценты.

assembleDebug, 100 Android/JVM-тестов и lintDebug прошли. Проверены оба режима и матрица 0/1/2/5 ошибок, нулевой баланс, потолок 25, новое независимое задание с тем же словом, повторное событие с новым ID, поздние callbacks озвучки, восстановление после пересоздания Activity, JSON-экспорт/повторный импорт незавершённого вопроса и сохранение очереди закрепления. Миграционный тест воспроизводит старые −3 и −1 в двух открытых вопросах: миграция сохраняет проценты/цель, затем правильные ответы доводят суммарный итог этих вопросов до −1 и +0,5 соответственно. UI-тесты проверяют реальные +0,5% и −1% в итоговой таблице и отсутствие дополнительных списаний после третьей/четвёртой ошибки.

Проверки выполнены в Robolectric API 28, физический Android не использовался. Словарь, справочные карточки, стабильные ID и DailyTracking.kt совпадают с предыдущим коммитом. Подпись совпадает с APK 0.5.1, applicationId прежний. versionCode=36, versionName=0.5.2. Устанавливать поверх предыдущей версии без удаления/очистки данных.
